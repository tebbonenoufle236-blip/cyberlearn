# CyberLearn — دليل التشغيل على XAMPP

## 1) خطوات التشغيل

1. انسخ مجلد `cyberlearn-fixed` بالكامل إلى:
   `C:\xampp\htdocs\cyberlearn` (Windows) أو `/Applications/XAMPP/htdocs/cyberlearn` (Mac) أو `/opt/lampp/htdocs/cyberlearn` (Linux).
2. شغّل **Apache** و **MySQL** من XAMPP Control Panel.
3. افتح `http://localhost/phpmyadmin` واستورد ملف `database.sql` (Import) — هذا ينشئ قاعدة البيانات `cyberlearn` وجدول `users`.
4. افتح الموقع من المتصفح عبر: `http://localhost/cyberlearn/index.html`.

بيانات الاتصال في `config/database.php` هي الإعدادات الافتراضية لـ XAMPP (`root` بدون باسورد). إذا كنت قد غيّرت باسورد MySQL، عدّل القيم هناك.

## 2) الأخطاء اللي كانت موجودة وتم تصليحها

- **main.js**: أول سطرين كانوا يعملوا `getElementById("welcomeButton").addEventListener(...)` بدون التأكد إذا الزر موجود. الزر موجود فقط في `index.html`، فأي صفحة تانية (تسجيل، دخول...) كانت تطلع خطأ JavaScript من أول سطر، وهاد كان يوقف تنفيذ باقي الملف بالكامل — يعني كل كود التحقق من فورم التسجيل (username, password, confirm password) وأزرار "إظهار كلمة المرور" ما كانت تشتغل أبداً. تم إضافة `if (button) { ... }`.
- **index.html**: id الزر كان `welcomebutton` بأحرف صغيرة بينما main.js يبحث عن `welcomeButton` — تم توحيدهم.
- **index.html**: كان ناقص وسم إغلاق `</section>` قبل قسم "أحدث المقالات"، فصار القسمين متداخلين بشكل غير صحيح في الـ HTML. تم إصلاحه.
- **index.html**: الروابط كانت تشير إلى `article.Html` (بحرف H كبير) بينما اسم الملف الفعلي `article.html` — على XAMPP وويندوز ما بيأثر لأن نظام الملفات ما بيفرّق بين الأحرف، بس لو رفعت الموقع على استضافة Linux لاحقاً هاد بيسبب صفحة 404. تم تصحيحه لأحرف صغيرة.
- **register.Html و videos.Html**: نفس مشكلة الأحرف الكبيرة بأسماء الملفات نفسها. تم إعادة تسميتهم إلى `register.html` و `videos.html` بأحرف صغيرة بالكامل لتفادي مشاكل عند النشر على سيرفر حقيقي.
- **login.html**: الفورم ما كان فيه `action` ولا `method`، يعني الضغط على "تسجيل الدخول" ما كان بيعمل شي غير إعادة تحميل نفس الصفحة. تم ربطه بـ `login.php` عبر `POST`، وأضفت زر "إظهار كلمة المرور" (كان الكود جاهز أصلاً بـ main.js بس ناقص الزر بهاي الصفحة).

## 3) الأجزاء اللي كانت ناقصة تماماً وتمت إضافتها (الـ Backend)

- `config/database.php` — ملف الاتصال بقاعدة البيانات (كان مطلوب من `register.php` عبر `require_once` لكنه غير موجود أصلاً).
- `database.sql` — لإنشاء قاعدة البيانات وجدول `users` (id, username, email, password, created_at).
- `login.php` — لم يكن موجوداً إطلاقاً؛ يتحقق من البريد وكلمة المرور (`password_verify`) ويفتح جلسة (session).
- `logout.php` — لإنهاء الجلسة والرجوع لصفحة الدخول.
- `dashboard.php` — صفحة ترحيب بسيطة تظهر بعد نجاح تسجيل الدخول أو إنشاء الحساب، ومحمية بحيث لا يدخلها إلا مستخدم مسجّل دخوله.
- `register.php` — تم تعديله بحيث بعد نجاح إنشاء الحساب يسجّل دخول المستخدم تلقائياً ويحوّله إلى `dashboard.php` بدل ما يوقف على رسالة نصية بدون أي وجهة.

## 4) ملاحظات ومقترحات لمرحلة لاحقة (مش أخطاء، بس تستحق الانتباه)

- في `articles.html` الروابط الأربعة كلها بتوجه لنفس `article.html` (محتوى "ما هو الأمن السيبراني" بس)، فمقالات الـ malware والـ phishing والـ networking ما إلها صفحات محتوى فعلية بعد. لما توصل لمرحلة ربط المقالات بقاعدة بيانات، فكر تعمل جدول `articles` وصفحة وحدة ديناميكية `article.php?id=` بدل صفحات ثابتة.
- الصور (`assets/images/*.jpg`) والفيديوهات (`assets/videos/*.mp4`) المشار إليها في الأكواد غير موجودة ضمن الملفات المرفوعة، فحطيتلك ملاحظة داخل `assets/README.txt`. لازم تضيف الملفات الحقيقية بنفس الأسماء.
- الـ navbar حالياً ثابت في كل صفحة (روابط "تسجيل الدخول" و"إنشاء حساب" تظهر دائماً حتى لو المستخدم مسجّل دخوله فعلاً). تحسين لاحق ممكن: تحويل الـ header لجزء PHP مشترك (`include`) يتحقق من `$_SESSION` ويعرض "لوحة التحكم / تسجيل الخروج" بدلاً منهم.
- بما إنك بتتعلم OOP بـ PHP، الكود الحالي (register.php/login.php) مكتوب بأسلوب procedural عشان يبقى متناسق مع اللي كان موجود أصلاً. لاحقاً ممكن تحوّل الاتصال بقاعدة البيانات وعمليات المستخدمين لصف `Database` و `User` زي ما عملت بمشروع الـ Task Manager.
